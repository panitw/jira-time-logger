## 2026-07-25 — Run opened

- **Trigger (user, verbatim):** "Currently the UX is terrible (see the screenshots). Let's revamp the UX/UI"
- **Inputs supplied:** 2 screenshots of the shipped toolbar popup (Today tab, scrolled top and scrolled bottom).

### Codebase grounding (observed, not decided)

- Stack: WXT + React 19 + Tailwind v4 (CSS-first `@theme`) + shadcn/ui (neutral base, CSS vars) + lucide icons + Radix (dialog, tabs).
- Surfaces in code: `entrypoints/popup` (toolbar popup), `entrypoints/options` (options page), `entrypoints/content.ts` (inline Jira banner), `entrypoints/background.ts` (badge + notifications).
- Existing tokens live in `styles/globals.css` (`--color-accent: #6b5b95`, slate neutrals, state colors, 14px root).
- Prior spec: `_bmad-output/planning-artifacts/ux-design-specification.md` (132 KB) — inherited by reference as a source, not re-authored.

### Screenshot observations (defects seen, no fixes proposed yet)

1. Today and Week render **stacked in one scroll** despite being tabs — `TabsContent` uses `forceMount` with no hidden state (`entrypoints/popup/App.tsx:194-205`).
2. Popup has `min-w-[360px]` and no max — content pushes it to Chrome's 800×600 ceiling, so the layout is neither the 360px column the prior spec assumed nor a designed wide layout.
3. Nested scroll: a 55-item ticket list scrolls **inside** an already-scrolling popup.
4. "below target" repeated 5× in red across the daily-totals row — reads as alarm, contradicts the prior spec's "never alarming" state-color intent.
5. Empty-value glyph `——` renders as broken content ("Sat, Jul 25 · —— / 8h").
6. Flat hierarchy: every block ("Today", "Logged today", "Pick a ticket to log", "Week of Mon, Jul 20") carries similar visual weight; no primary action is obvious.
7. Mixed type systems: monospace ticket keys beside proportional summaries, ragged left edges in the list.
8. No grouping/containment — sections float on one background with no cards, dividers, or elevation.

## 2026-07-25 — Post-output decisions

### D14. `◐` split, and PTO renamed to "Time off"

Note: *"Split it and I also want to change the name from PTO -> Time Off to make it clear."*

The producer used `◐` for three unrelated things — PTO, restricted visibility, and live search — while KKP
defines it as *recomputing/verifying*. A booked holiday could read as "still calculating."

- **Time off takes `◆`** (solid diamond, `{colors.legacy-purple}`): a settled, intentional, finished day.
- **`◐` keeps only in-flight/unknowable meanings**: loading, searching live, worklogs a manager can't see.
  It is no longer a day status at all.
- The day-status vocabulary is now `✓` met · `◔` partial · `●` nothing logged · `◆` time off · weekend.
- Glyph choice is facilitator's; the *split* is Note's. `◆` was picked for a distinct silhouette at 11px
  while staying in the geometric monochrome family. Easily changed without disturbing the split.

**Rename scope — copy only.** All user-facing strings, labels, and accessible names read "time off".
Internal identifiers (`ptoSubtask`, `PtoQuickAction`, `PtoPopover`, storage keys) stay — renaming buys
users nothing and churns a large test surface. The Jira subtask `KNP-99 PTO` is customer data and is
displayed verbatim where its summary is shown.

Both spines updated accordingly.

### D16. Status marks become lucide icons, not text glyphs

Note asked for Font Awesome; on being shown that `lucide-react` is already the project's declared icon
library, confirmed *"lucide-react is fine."*

**Why Font Awesome was the wrong fit here** (surfaced before the switch, not after):

- FA is not a dependency; lucide is, and `components.json` names it as *the* icon library. Adding FA means a
  second icon set in a Chrome extension — either a webfont (CSP-hostile, needs bundling) or another React
  package tree.
- **FA Free has no quarter-fill circle.** `circle-quarter` / `circle-three-quarters` are Pro-tier. The free
  set would have forced *partially logged* and *in-flight* onto the same `circle-half-stroke` — collapsing
  the exact overloading D14 had just split apart.

**Mapping** (`DESIGN.md` frontmatter `icons:` is authoritative):

| Was | Now | State |
|---|---|---|
| `✓` | `CircleCheck` | target met |
| `◔` | `ChartPie` | partially logged |
| `●` | `Circle` filled | nothing logged / edited after approval |
| `◆` | `Diamond` filled | time off |
| `◐` | `LoaderCircle` | in flight |
| `◐` | **`EyeOff`** | restricted — not permitted to see |
| `✕` | `CircleX` | failed write |

Plus interface icons: `Search`, `CornerDownLeft`, `Plus`, `Pencil`, `Trash2`, `ArrowUpRight`,
`ChevronDown/Left/Right`, `WifiOff`, `Undo2`, `Minus`. All verified present in the installed lucide 0.460.0.

**Three things the swap bought, beyond looks:**

1. **A third de-overloading, free.** Restricted-visibility no longer shares a mark with in-flight — it's now
   literally an eye with a line through it. The geometric-glyph family couldn't express that; an icon set can.
2. **Better accessibility, not neutral.** Text glyphs sit in the accessibility tree and get announced —
   a screen reader saying "black diamond" before "time off" is noise. Icons are `aria-hidden` SVG with the
   meaning in the adjacent text.
3. **Deterministic rendering.** `◔` in particular has patchy platform-font coverage and no guaranteed
   presence in the bundled Latin subset. SVG renders identically everywhere.

**Consequence for copy:** strings no longer embed their mark. `"✓ Target met — 8h logged"` becomes
`"Target met — 8h logged"` with the icon composed as a sibling — which also keeps `STRINGS` maps clean and
keeps the glyph out of the screen reader's path. Recorded in EXPERIENCE.md § Voice and Tone.

Both spines and all Epic 7 acceptance criteria updated. Story 7.6 gains a requirement that the vocabulary
live in **one shared component** mapping status → icon + colour token + label, so no surface re-implements it.

### D18. The banner is a rail, not a bar

44px white ground, a 3px Legacy-Purple spine on the left edge, one 18px purple mark, purple-tinted hairline
beneath. Sits above Jira the way a bookmarks bar does — structurally present, chromatically quiet, never
mistakable for a warning. Down from today's 56px.

**Brand identity without gradient, motif, or brand fonts** — the central problem of the handoff — is carried
by hue (the exact `#594F74` in under 2% of the area), purple-tinted neutrals (`#E4E3EC`, deliberately not
Jira's `#DFE1E6`), geometry carried over verbatim (6px radii, 28px controls, the popup's button
proportions), and tabular numerals, which work on any system face.

Captured as a new `## The Guest Surface` section in DESIGN.md — this is a reusable idea, not a one-off:
*how the system expresses itself where it owns no chrome.*

### D19. Kanit is NOT shipped to the banner

Producer's recommendation, accepted. It costs a `web_accessible_resources` entry and a permission-warning
risk at install, and any Jira instance with a strict `font-src` falls back silently — so the surface you'd
actually be designing for is the fallback. A 44px rail is not where anyone reads type. `{typography.guest}`
is now a named token, not an oversight.

### D20. Three implementation findings that changed Story 7.11's ACs

1. **Expansion must not change the rail's height.** It stays 44px and swaps right-hand contents; the hours
   field takes the space the action vacated. The `body padding-top` is written once and Jira's page never
   reflows twice per interaction. The rail's height is a *layout contract*.
2. **No keyframes are needed anywhere** — entry, expand, exit are all `transform: translateY()` with
   `transition` in the inline style string. This removes the main apparent obstacle to inline-styles-only.
3. **Hover and focus are JS** — listeners writing `el.style.background` / `boxShadow`; reduced motion via
   `matchMedia` setting `transition: 'none'`.

Also: below ~860px the eyebrow and "Open extension" drop and the state truncates, but **the contextual
action never wraps** — wrapping would change the height and break the contract.

### D21. Settings groups by what a thing *is*, not by topic

680px reading column left-aligned in the 1180px shell, labels above fields. Five blocks: Connection and
Reporting line are **fact tables with no input affordance**; Logging defaults is **the only region where
anything can be typed**; Diagnostics is facts plus one safe action; Disconnect is separated under a **grey
rule rather than purple**, in a sunk card with error ink, keeping its confirm dialog.

Chrome header carries identity, connection, last-synced, and the Week/Manager/Settings tab row — which is
the mechanism that actually folds two pages into one. No headline figure, correctly.

**Catch-all validation is neutral mid-typing, never red.** The dependent select simply waits. Only a
settled, wrong key earns amber, and it states what it did to the dependent field.

Labels adopted: Catch-all project key · Time-off subtask · Work-day target · Daily reminder · Approval
cycle — each with a one-line consequence beneath rather than a tooltip.
