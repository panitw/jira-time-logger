The brand problem, answered

Gradient, orbital motif and Kanit are all off the table. What's left is hue, geometry and number discipline — and that turns out to be enough, because those are the three things the popup and the banner can actually share pixel-for-pixel.

●The exact purple, in a tiny dose. A 3px spine and an 18px mark — under 2% of the bar's area. Recognition doesn't need coverage; it needs the right #594F74 next to the right neutral.
●Purple-tinted neutrals. Borders are #E4E3EC, not Jira's #DFE1E6. Sat next to each other in the mockup above, the rail reads as a different object — warmer, quieter — without a single saturated pixel.
●Geometry carries over verbatim. 6px radii, 28px control height, the 1px divider, the same button proportions as the popup's +0.5 / +1 row. Shape is the most CSP-proof brand asset there is.
●Tabular numerals everywhere. font-variant-numeric:tabular-nums works on any system face. The product's numbers look like the product's numbers.
On shipping Kanit here — don't

It costs a web_accessible_resources entry, a permission-warning risk at install, and a silent fallback on any Jira instance whose font-src is strict — meaning the surface you'd be designing for is the fallback anyway. The system stack at 10/12.5/13px is honest and legible, and a 44px rail is not where anyone reads type. Spend the manifest change somewhere it earns more.

Motion, inline-style-only
●No keyframes needed. Entry, expand and exit are all one property: transform:translateY() with transition set in the inline style string. Set the value, let the browser tween.
●Expansion doesn't grow the bar. It stays 44px and swaps its right-hand contents; the field appears in the space the action vacated. So the page never reflows twice, and the body padding-top the content script sets is written once.
●Hover without CSS: two mouseenter/mouseleave listeners per control writing el.style.background. Focus rings are focus/blur writing boxShadow. Both listed in the build notes.
●Reduced motion via matchMedia in JS — set transition:'none' and jump to the end state. No media query required.
Surviving fifty sightings a day

The bar states a number and stops. No icon parade, no progress bar, no colour that changes as the week slips — an amber bar on Thursday would be a scold, and the spines forbid it. The one moment it asks for anything is on a /browse/<KEY> page, where the ask is specific and almost always right. Everywhere else it is a fact you can ignore, which is the only thing that survives repetition.

Decisions on settings
●680px reading column, left-aligned in the 1180px shell. Labels sit above fields; field widths are sized to their content (180px for a project key, full width for a subtask title), which is itself a legibility cue.
●Four groups, weighted. Facts (Connection, Reporting line) are hairline-row tables with no input affordance. Choices (Logging defaults) are one padded card — the only place anything can be typed. Diagnostics is a fact table. Disconnect is a fifth, deliberately separated block.
●Disconnect at the bottom, under a grey rule instead of purple, in a sunk card, as an outline button with error ink — reachable by scrolling, never adjacent to anything you'd click routinely. It keeps its confirm dialog: it's irreversible in a way Clear cache isn't.
●The chrome header carries identity and connection, not a figure — plus the Week / Manager / Settings tab row, which is what actually folds two pages into one. Last-synced sits there because it's the one number that makes the header worth its height.
●Labels changed: “PTO subtask” → Time-off subtask; “Default hours” → Work-day target; “Reminder” → Daily reminder; “Fallback project” → Catch-all project key. Each gained a one-line consequence under it rather than a tooltip.
●Flag: round 1's surfaces still say “PTO”. The spine now says time off everywhere — the popup footer, the week legend and the KNP-99 row all need the string swapped. Say the word and I'll do it.

Notes back to you

The 55-ticket list

The list is not the job — logging today is. So the popup never renders 55 rows. It shows the four tickets you actually touched this week, ranked by recency, then hands the other 51 to search. Search is the browse mechanism, not a filter on top of a browse mechanism.

This also solves the teammate-ticket case for free: search hits Jira live, so tickets that aren't yours are reachable through the same control. One list, one scroll region, no tabs.

Long GAPI summaries

Key and summary sit on separate lines, so an 80-character summary truncates on its own line without shoving the key around. In the resume card the summary gets two lines; in list rows, one with an ellipsis. Rows stay the same height, so the list scans.

●Elevation on the data canvas. Used as licensed: purple chrome → white cards → hairline rows. Three levels, no more.
●Two amber tints added — #FFF8EC fill, #EDD3A6 border, #7A3E06 text (5.9:1). Derived from --status-dirty; no new hue.

●Empty value glyph is ·, replacing ——. A dashed "no hours" chip is used where the emptiness is meaningful.
